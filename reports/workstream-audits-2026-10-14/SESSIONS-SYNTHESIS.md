# SESSIONS synthesis: context + handoff mechanics (6 workstreams, process only)

Sources: web-redesign (86 sess/341 runs/64 handoffs), foundation-naive-e2e (131/470/44), app-moneypuck (113/399/39), shared-demo-tenants (63/259/37), landing-flow-demo (62/190/22), auth-infra (28/121/11). All findings confirmed in ≥2 files; conflicts resolved in favor of files.

## 1. Useless patterns to kill (per-run waste)

1. Static framework re-sent per run: canonical-context only ~6 md5s (6574/6810/8618/9737 B) × hundreds of runs. Foundation: ~3–4 MB re-sent over 470 runs for zero new bytes. Session-start 2973 B byte-identical ×13 (web-redesign). Worker framework sha 2380 B ×12 scouts, 3383 B ×5 reviewers (landing). Job02 loop re-sent 9737 B unchanged 3× in 11 min (moneypuck).
2. Session-block stubs: sane-session 161–197 B ×285 (moneypuck/foundation), zero refresh across jobs 7→11 (landing); 176 B phaseless stub on 5/121 runs (auth-infra). Missing in 100+ sessions (85 web, 130 foundation, 107 moneypuck) with zero completion impact — dead channel.
3. Fixed handoff boilerplate: 1.2 KB envelope ×11 all-identical keys (auth-infra; kickoffs 1272 B to carry ~50 B bodies); fixed 124-char evidence ×64 (web-redesign); owner-authority prose in 29/44 handoffs (foundation, 66%).
4. Failure retry as new-ID resend: 217 B starter failed ×2 then retried as fresh starter on other harness, linked only by prose (moneypuck); 2113 B FAILED re-sent 7.5 h later under new requestId, original stays FAILED (demo-tenants).
5. Prose-pointer handoffs: 62/59 B design→engineering "see SDD" (demo-tenants); 57–60 B phase-starts + createNew (landing, correct there, wrong cross-phase); research replies ≈ question length, findings only via re-read files (auth-infra).
6. 1.4 MB canonical-context outlier (full conversation dump, web-redesign) + 47 KB curation mega-submission (landing): unbounded-history inclusions with no byte budget.

## 2. Redundant documents / duplication

- Handoff bodies: consecutive-blob similarity mostly <0.10 — freshly composed, good (foundation). No input duplication in revision handoffs (landing). Keep composing; kill only the fixed parts above.
- Research registration: 43 rows for ~10 topics (10 REPORT.md + 33 *-evidence.md fragments, foundation). Readers list dirs to find the 10 real reports.
- Test reports: 63 files/~1 MB with byte-identical before/after pairs ×3 verified by md5 (demo-tenants). Doubles write+scan cost, never inlined.
- `jobs_registered` re-broadcasts full job array each time (7→9→11, landing). 1:1 job↔report mirroring, 52 md files.
- Evidence-dir navigability: 370 files with no per-pass manifest; each worker re-discovers paths (moneypuck).
- Pre-staged verification (4 checkpoints ~25 KB) with zero handoffs to execution — inert until first execution handoff re-derives relevance (auth-infra).

## 3. Frequent gaps that docs/structure should cover

1. Rejection reasons never recorded: 5 design approvals with 2-char user_references, new doc but no delta fed forward (web-redesign); 4 design approvals with zero handoffs between rounds 1–3, in-chat-only evolution (auth-infra). Rework signal = full-doc diffs only.
2. No gate re-entry on scope growth: jobs 7→11 under single planning approval; expansions with no new phase_approved (landing). Steers ("shortlist bar", Job-11 instruction) absorbed with zero context change, no `steer_recorded` op (landing).
3. No negative-requirement section: Google no-email-prompt rule missing from design + cp1–cp4 specs, first asserted cp5 post-"complete" (demo-tenants). No `authPatterns`/constraint key exists in any handoff key-set.
4. Supersede/secrets live in owner prose: "22-table proposal superseded", "passwords supplied by owner", RDS host in 8 KB handoff — no `Status: superseded-by`/secrets-pointer front-matter (foundation). Each redirect costs a bespoke handoff.
5. Artifact ≠ delivery: canonical-context on disk yet "not confirmed" + framework-missing ×72 (moneypuck); 0/259 runs with framework evidence yet workstream deployed (demo-tenants, pre-framework era unmarked). `.delivered` 0-byte flags ×182 present on ~60% of candidates, inconsistently (all workstreams).
6. SDD `provide` ran 4× at phase starts then never again despite invalidating renames/new jobs (landing); stale `launch.agentFile` refs ×94–104 (web-redesign, foundation).

## 4. Ranked top 6 context+handoff optimizations

1. Content-addressed framework dedup (mechanism: hash-cache). Problem: 6.5–9.7 KB static templates + 2973 B essay re-sent per run (all 6 workstreams; 3–4 MB/set). Evidence: 6 md5s/175 files, 13× identical 2973 B, 12× same worker sha. Mechanism: send once per native session; per-run carry `framework_hash + version` + delta only; byte budget + truncation notice kills 1.4 MB dumps. Effect: ~7–10 KB saved per run (~3–4 MB per 470-run workstream); closes tight-loop resend failure mode.
2. Delivery receipts, fix-or-kill Session block (mechanism: delivery receipts). Problem: 176–197 B stubs ×285 with 100+ missing-session-blocks at zero completion impact; 182 0-byte `.delivered` flags; artifact-present/confirmation-absent (72 framework-missing). Evidence: all 6 workstreams. Mechanism: single receipt (hashes of session-start/canonical + transcript-confirmed bool, written atomically); either deliver the ~190 B pointer reliably or bless handoff+files as the channel; era-tag pre-framework sessions. Effect: eliminates ~55 KB stub writes + unattributable-context audit noise; closes "delivered but unseen" ambiguity.
3. Structured constraint keys + negative requirements (mechanism: structured constraint keys). Problem: 62 B prose-pointer cross-phase handoffs; Google-flow rule escaped to post-complete; kickoffs carry features not constraints. Evidence: demo-tenants (cp1–cp4 zero hits, cp5 20 hits), auth-infra (no constraint key in 11/11 key-sets). Mechanism: `authPatterns/never-X-on-flow-Y` keys on design→planning handoffs; mandatory negative-requirement spec section carried every checkpoint. Effect: rule would fail at cp1 not post-complete; bans pointer handoffs for cross-phase transfers.
4. Gate re-entry + auditable rework deltas (mechanism: gate re-entry). Problem: design approval loops (5 rounds/2 h; 4 rounds in-chat-only) with zero new handoff context; jobs 7→11 under one approval; steers invisible. Evidence: web-redesign, auth-infra, landing. Mechanism: `jobs_registered` growth post-approval requires new `phase_approved` (or auto-reset planning in_progress); each failed approval appends `rejected_hash + 1–2-line reason`; approval record stores handoff-IDs + doc-hashes since last approval; add `steer_recorded` op + re-provide SDD on post-approval change. Effect: distinguishes re-approval-of-same vs new-context; rework becomes auditable file edits not bespoke handoffs.
5. Same-requestId retry semantics (mechanism: revision++ + supersedes-links). Problem: new-ID resends strand FAILED originals; harness switches (cc→oc) unreadable as one incident; trimmed 217 B starters instead of full input. Evidence: moneypuck (2 failed), demo-tenants (429, 7.5 h gap). Mechanism: retry same `requestId` with `revision++`, carry/link full failed input, record harness switch + supersedes-link in evidence. Effect: closes stranded-FAILED + prose-only-linkage failure modes; one incident reads as one.
6. Registration hygiene: tiers, single-write evidence, delta broadcasts (mechanism: WIP registration). Problem: 43 topic rows for 10 topics; identical before/after test pairs; full job-array rebroadcasts; 370-file evidence dirs with no manifest. Evidence: foundation, demo-tenants, landing, moneypuck. Mechanism: REPORT.md (registered decision) vs *-evidence.md (unregistered attachment); test harness writes one file + sha/empty-marker, cap raw logs per checkpoint; `jobs_registered` sends deltas; per-pass manifest/pointer file; constant-string variance check forbids fixed evidence/boilerplate (kills 124-char ×64, 1.1 KB ×11, owner prose → `delegatedBy: owner` flag, target p50 message <1.5 KB). Effect: topic rows 43→~10; halves test-report write/scan; reserves message bodies for verdicts/paths/decisions.
