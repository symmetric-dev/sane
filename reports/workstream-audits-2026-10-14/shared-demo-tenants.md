## What worked

1. **Demo-protection as a first-class spec + checklist.** Frozen-surface table, permitted-edits table, and 8-point checklist gave every reviewer a mechanical rubric. Checkpoints 2/3/5 record checklist items 1–5 with file:line branch-guard reasoning. Replicate this for any workstream touching live behavior.
2. **Research that grades its own confidence.** The CloudFront report says what it didn't do (no live test) and what follows (operator confirms post-deploy). SDD and checkpoint-1 test report carry that caveat forward instead of dropping it.
3. **Verification specs written before testing, amended openly.** Checkpoint amendments (cp2 cross-agency denial + Google 401 corrections; cp5 exhausted-rounds permission) went through planning↔execution handoffs with rationale, not silent edits. The failed handoff (`exec-cp2-verification-conflicts-01`, terminal App-run failure) was followed by completed lookahead/amendment handoffs — failure handled, not hidden.
4. **Test reports that record exit codes and supersede honestly.** Checkpoint 5's table shows initial exit 1/2 runs (collection collision, 15 failures) corrected to final exit 0, with what changed (tests/fixtures only). Checkpoint 1 records harness failures vs behavior failures. This is the "done" evidence bar.
5. **FINAL_REPORT honesty about residual risk.** Pending browser checks, untested user commits, provisional tests, scale follow-up (canonical-email full scan → needs indexed lookup) are all named with owners. Nothing claims more than its evidence.
6. **Plan split notes preventing file collisions.** Job file-ownership assignments (job 06 gathers all frozen-Google edits; job 08 owns all shared web files) plus explicit parallel/sequential rules — enabled 09/10/11 parallelism safely.
7. **Fast phase cadence with re-approval, not rework avoidance.** Engineering approved twice (`looks-good`, then `v2` after spec amendments); planning approved twice (`with-skills`, then `replan-google`). Re-approval normalized mid-course correction.

## What didn't

1. **User found a design miss late: Google flows asked for email.** After checkpoint 4 (full web onboarding "complete"), the user's visual pass caught that Continue-with-Google asked for email on all three new pages — violating the established demo pattern. Required 3 extra jobs (12–14), 2 extra checkpoints (5–6), engineering re-amendment + planning re-approval. Root cause: design specified email-keyed provisioning before redirect; nobody checked the OAuth-never-asks-email invariant until the browser. Lesson: add an "established-patterns" review step to design for auth flows.
2. **Checkpoint 2 verification blocked on environment + spec contradictions.** Workspace pytest failed on empty `AWS_PROFILE` (ProfileNotFound before any test body); spec simultaneously demanded denials contradicting frozen baseline (`founder_required` vs actual `agency_access_denied`; opaque 202 vs actual 401). Cost a blocked-verification handoff + failed handoff + amendment cycle. Environment-failure rule worked (stopped, reported), but spec-vs-baseline contradictions should have been caught at plan time by diffing spec assertions against frozen code.
3. **Demo-reset pre-existing breakage carried as xfail throughout.** `demo_reset.py` revision guard rejects current head `f2b7c4d18e53` (predates workstream); every checkpoint carries a strict xfail + follow-up note. Correct scoping (not this workstream's job), but "done" ships with a known-broken reset path and only source-review (not execution) evidence that reset scope is demo-limited.
4. **Root lint baseline broken; worked around by scoping.** `bun run lint` fails on untouched files; checkpoints lint only changed files. Same pattern as elsewhere — repo-level hygiene debt pushed into every test report's findings.
5. **Post-deploy user commits outside execution scope.** `5a815ae`, `c285a13` touch auth/codecs/Google modules post-deployment, user-verified in prod only. FINAL_REPORT discloses; still a process gap — no re-verification hook after user hotfixes.

## Repetition/duplication

- **test-reports/ bloat is real but mostly signal.** 63 files / 1.0 MB. Genuine duplication: `*-production-before.diff` vs `*-after.diff` are byte-identical (`cmp` confirms for cp5 and cp6 pairs; same for sha256 pairs) — the "production preservation" ritual stores every file twice to prove no change. Before/after OpenAPI diffs (28 KB ×2) likewise identical. Keep the comparison log; drop one copy of each identical pair.
- **Intermediate pytest logs accumulate rather than roll up.** cp5 keeps initial + full + followup + focused + concurrent + final logs (5 failing/superseded runs retained alongside final). The .md already narrates the progression; retaining all intermediates doubles the dir. Keep final + one "reconciliation" log; archive the rest.
- **Environment-prerequisite boilerplate** (local-stack skill + 6-line docker compose prefix + AWS-unset explanation) repeats verbatim in verification specs cp2/cp3/cp5 and in test reports. Candidate for a shared snippet reference.
- **resources/ templates vendored per workstream** (9 files, 40 KB here). Identical sets across workstreams; should live once at `.sane/` root or be versioned centrally.
- **Job spec/report/test-report triple overlap.** Job spec states intent, report restates implementation file-by-file, test report re-narrates behavior + commands. Some restatement is evidence; but e.g. `13-baseline-*`/`13-preflight-*` logs in `reports/` duplicate `test-reports/` checkpoint-5 logs covering the same runs.

## SANE-process observations

- **Most complete lifecycle in scope; use as "done" reference** for FINAL_REPORT structure, test-report exit-code tables, and demo-protection checklist reuse. But "done" here still means "deployed + user happy-path confirmed, ~10 browser edge checks pending" — calibrate the label.
- **Handoff volume (37) is coordination cost made visible.** Planning↔execution↔engineering round-trips resolved real conflicts (cp2 denials, cp5 expiry semantics, Google replan). The single failed handoff (App run terminal failure, not content rejection) shows infra flakiness in the handoff path itself — worth tracking as a metric.
- **Re-approval worked twice without derailing.** Engineering v2 + planning replan-google kept hashes meaningful. Contrast with workstreams that amend docs without re-approval.
- **Single research report, tightly scoped, consumed.** 1 topic → cited by SDD → caveat propagated to test report → operator check. The research→design→verification chain actually functioned here.
- **Workstream status still `open` despite execution `approved` + FINAL_REPORT + prod deploy.** Either close-out is manual/pending or `done` transition isn't wired — check whether `open` post-approval is normal or this reference case was left unclosed.
- **Biggest process improvement pointer:** a design-time "frozen-baseline assertion check" (spec claims vs actual frozen code/denials) would have prevented the cp2 block; an "established auth-patterns" checklist would have caught the Google-email miss before 11 jobs were built.
