# Optional sane-science / marimo integration: current SANE architecture audit

Scope: read-only audit of `/Users/beto/sane` on 2026-10-06. Marimo is treated only as an assumed local server component; no external marimo capabilities, flags, authentication, embedding, or version support were researched. No tests, builds, browser verification, application changes, or skills/context changes were performed. Only this notes file was added. App source was already dirty (including `src/bridge.ts` and `frontend/browser-{tabs,view}`); evidence describes the current working copy, not exclusively committed behavior. All links below are local primary-source files with line ranges; **Current** means observed implementation, **Proposal/Inference** means a recommended change, not an existing capability.

## 1. What actually renders the App, and where can a notebook view fit?

### Takeaway

**Current:** SANE App is a Bun-served React browser application with installable PWA presentation, not an Electron/Tauri/native desktop webview. A dedicated optional Science view can fit existing feature-provider/sidebar/header/content seams, but the current Browser view is an unproxied cross-origin iframe preview, not a managed local-app integration framework. [Dependencies](../../packages/sane-app/package.json#L11-L41), [browser build](../../packages/sane-app/src/asset-build.ts#L75-L87), [React entry](../../packages/sane-app/frontend/main.tsx#L1-L13), [PWA tracking](../../packages/sane-app/frontend/pwa-install.ts#L16-L37).

### Cited Findings

- **Current UI technology:** React 19, React DOM, CodeMirror, xterm, and `sane-core` are declared dependencies; browser entry mounts `<App />` with `createRoot`. Bun builds `frontend/main.tsx` as browser ESM. No native shell is evidenced by these app entry/build/dependency paths. [Package](../../packages/sane-app/package.json#L11-L41), [entry](../../packages/sane-app/frontend/main.tsx#L1-L13), [build](../../packages/sane-app/src/asset-build.ts#L6-L6), [build invocation](../../packages/sane-app/src/asset-build.ts#L75-L87).
- **Current installed-app behavior:** install tracking uses `display-mode: standalone`, `beforeinstallprompt`, and `appinstalled`; it is browser/PWA logic rather than a native embedded-browser API. [PWA tracking](../../packages/sane-app/frontend/pwa-install.ts#L16-L37).
- **Current navigation is store-driven, not a URL router:** `ReadyWorkspace` gets `view`, `workspaceId`, and `worktreeId` from the catalog external store and navigates through `catalog.navigate`. The frontend saves a revisioned bookmark via `/api/navigation`; no React Router integration appears in these controlling paths. [Shell navigation](../../packages/sane-app/frontend/app.tsx#L95-L100), [navigate](../../packages/sane-app/frontend/app.tsx#L139-L174), [catalog](../../packages/sane-app/frontend/catalog.ts#L30-L73).
- **Current backend persisted view union:** `chat`, `code`, `git`, `terminal`, `workstreams`, `history`, `config`; the backend validator explicitly allows those IDs. **Browser is intentionally frontend-only**, preserving the prior persisted view when other selections change. This is not an accidental backend omission. [Contract](../../packages/sane-app/src/catalog-contract.ts#L35-L37), [validation](../../packages/sane-app/src/catalog.ts#L260-L277), [client-only Browser contract](../../packages/sane-app/frontend/catalog.ts#L5-L8), [client persistence handling](../../packages/sane-app/frontend/catalog.ts#L45-L54).
- **Current feature composition:** `App` imports feature-owned providers, headers, sidebars, and views. The sidebar selects conversations, files, Browser tabs, or settings based on `viewGroup`; providers remain above the responsive shell. Header and main content choose corresponding feature components. This is a direct composition seam, not a contributed-view registry. [Imports](../../packages/sane-app/frontend/app.tsx#L7-L37), [sidebar/providers](../../packages/sane-app/frontend/app.tsx#L175-L213), [header/content](../../packages/sane-app/frontend/app.tsx#L216-L275).
- **Current desktop/mobile layout:** one sidebar composition serves the desktop sidebar and a mobile modal drawer. `WorkspaceShell` owns responsive layout, not per-feature services. [Shell](../../packages/sane-app/frontend/workspace-shell.tsx#L26-L57).
- **Current navigation definitions are static:** groups and destination icons are coded in `nav.tsx`; destinations come from `NAVIGATION_HOTKEYS`. Commands currently register destinations even when their button is hidden, so a disabled Science feature must gate commands as well as visible navigation. [Groups/destinations](../../packages/sane-app/frontend/nav.tsx#L46-L86), [hotkeys](../../packages/sane-app/frontend/navigation-hotkeys.ts#L3-L10).
- **Current Browser tab ownership:** up to eight tabs, saved in device-local `localStorage` per `workspaceId`; tabs contain arbitrary HTTP(S) URLs, not notebook IDs, server handles, or worktree bindings. [Tab model/persistence](../../packages/sane-app/frontend/browser-tabs.ts#L1-L62), [provider/sidebar](../../packages/sane-app/frontend/browser-view.tsx#L11-L55).
- **Current Browser transport/security:** source comment explicitly says “No proxy”; localhost resolves on the frontend device. Sandbox grants scripts and same-origin alongside forms/popups/downloads. Address submission and restored frames both reject SANE's own origin. Cross-origin frames are used directly; docs in the UI warn about third-party cookies, frame restrictions, and HTTP-in-HTTPS. [URL policy](../../packages/sane-app/frontend/browser-tabs.ts#L7-L15), [sandbox](../../packages/sane-app/frontend/browser-view.tsx#L7-L9), [limitations](../../packages/sane-app/frontend/browser-view.tsx#L64-L76), [guards/frame](../../packages/sane-app/frontend/browser-view.tsx#L97-L125).
- **Current view lifetime:** Browser frames lazily start after visiting and stay mounted across main-view switches. Chat also remains mounted while hidden, expressly to retain native input state. Main views are otherwise mutually selected; there is no simultaneous chat-plus-notebook split layout in this composition. [Browser lifetime](../../packages/sane-app/frontend/browser-view.tsx#L80-L94), [chat/content lifetime](../../packages/sane-app/frontend/app.tsx#L255-L275).

### Inferences

- **Proposal:** add a dedicated Science adapter/view (`science-view.tsx`, `science-client.ts`, `science.css`) rather than make arbitrary Browser tabs authoritative notebook sessions. Reuse shell composition patterns and mounting behavior, not arbitrary URL persistence. Keep notebook identity and runtime state server-owned; UI selections may be client-local initially. [Supporting seam](../../packages/sane-app/frontend/app.tsx#L175-L213), [existing lifetime pattern](../../packages/sane-app/frontend/browser-view.tsx#L80-L94), [current tab limitations](../../packages/sane-app/frontend/browser-tabs.ts#L1-L62).
- **Proposal:** simplest UI can add `science` as another frontend-only leaf, explicitly updating the special-case persistence logic so it never reaches the current backend validator. If restoring Science across devices/reloads is required, instead extend the backend bookmark contract and validator deliberately. These are alternatives, not both required. [Client-only precedent](../../packages/sane-app/frontend/catalog.ts#L45-L54), [persisted contract](../../packages/sane-app/src/catalog-contract.ts#L35-L37), [validator](../../packages/sane-app/src/catalog.ts#L260-L277).
- **Proposal:** “alongside AI research” can mean switching between retained Chat and Science surfaces for an MVP. If it means genuinely simultaneous interaction, introduce an explicit optional split/pinned notebook region at `ShellContent`/`WorkspaceShell`, with responsive collapse and scope labels; current tabs alone do not satisfy that stricter requirement. [Current mutually selected surfaces](../../packages/sane-app/frontend/app.tsx#L255-L275), [responsive shell](../../packages/sane-app/frontend/workspace-shell.tsx#L34-L57).
- **Security inference:** do not remove the Browser own-origin guard to embed a notebook reverse proxy on the App origin. A frame with scripts plus same-origin would share the host origin; cookie `HttpOnly` does not prevent same-origin authenticated API requests. Use a dedicated trusted Science surface with a reviewed isolation policy, ideally a separate origin. [Frame grants/guard](../../packages/sane-app/frontend/browser-view.tsx#L7-L9), [frame](../../packages/sane-app/frontend/browser-view.tsx#L119-L125), [cookie/auth boundary](../../packages/sane-app/src/bridge-auth.ts#L35-L37), [cookie issuance](../../packages/sane-app/src/bridge-auth.ts#L62-L67).

### Gaps

- Marimo embedding compatibility, sandbox requirements, websocket URL construction, base-path support, and unsaved-edit behavior were intentionally not investigated. These must be qualified before selecting direct-origin or proxied transport. [Existing iframe constraints motivating the gap](../../packages/sane-app/frontend/browser-view.tsx#L64-L76).
- Product decisions remain: switchable view versus actual split screen; frontend-local versus persisted Science selection; local-only versus remote access. Existing App behavior supports browser remote access but not automatic remote reachability for preview localhost URLs. [UI limitation](../../packages/sane-app/frontend/browser-view.tsx#L69-L74), [App remote configuration](../../packages/sane-app/src/app-config.ts#L134-L142).

## 2. What backend, lifecycle, auth, configuration, and plugin seams exist?

### Takeaway

**Current:** the App bridge explicitly composes scoped services, an authenticated HTTP API, a terminal-only websocket handler, and bounded shutdown/ownership handling. No general SANE App extension framework was found in these entry/config/build/composition paths; the existing OpenCode plugin is a native-agent integration, not an App plugin host. **Proposal:** a single opt-in `sane-science` package plus a thin App adapter is sufficient; do not first build discovery, arbitrary plugin loading, contributed routes, or a generic event bus. [Bridge composition](../../packages/sane-app/src/bridge.ts#L40-L69), [config](../../packages/sane-app/src/app-config.ts#L9-L22), [HTTP entry](../../packages/sane-app/src/bridge.ts#L2112-L2145), [server websocket](../../packages/sane-app/src/bridge.ts#L3007-L3009), [native plugin](../../opencode/plugins/sane/index.ts#L1-L15).

### Cited Findings

- **Current package boundaries:** root is a private Bun workspace over `packages/*`. App depends on `sane-core`; CLI depends on core and native-client/MCP libraries. Core exports browser-safe contracts separately from server/domain operations. CLI entry delegates to `sane-cli`. App currently has some direct relative imports of CLI native integration helpers, so boundaries are practical rather than perfectly isolated. [Workspace](../../package.json#L1-L21), [App dependency](../../packages/sane-app/package.json#L40-L41), [CLI dependencies](../../packages/sane-cli/package.json#L1-L15), [core exports](../../packages/sane-core/package.json#L1-L12), [contracts safety](../../packages/sane-core/src/contracts.ts#L1-L9), [CLI entry](../../bin/sane.ts#L1-L13), [App-to-CLI imports](../../packages/sane-app/src/bridge.ts#L50-L55).
- **Current saved config is strict versioned JSON**, defaulting to `packages/sane-app/.config.json`. Duplicate keys and unknown top-level/nested keys are rejected; there is no accepted `extensions`, `science`, or arbitrary plugin-options bag. CLI options are allowlisted. Saved paths are config-relative, CLI paths invocation-relative. [Shape/unknown keys](../../packages/sane-app/src/app-config.ts#L9-L22), [JSON parsing](../../packages/sane-app/src/app-config.ts#L33-L61), [resolution/flags](../../packages/sane-app/src/app-config.ts#L64-L108).
- **Current configuration has no per-project Science opt-in:** selected config covers App data, execution cwd, server, concurrency, and native source selection. Setup initializes App state separately from `.sane`, refuses changed existing saved settings, and serializes resolved configuration. [Config shape](../../packages/sane-app/src/app-config.ts#L9-L15), [setup](../../packages/sane-app/setup.ts#L8-L42).
- **Current runtime config seam:** `runtimeOptions` converts saved config to bridge `Options`; `/api/config` returns signed-in capabilities. A new capability must be wired through both backend runtime conversion and frontend `Config`/capability types, not merely added to saved JSON. [Runtime conversion](../../packages/sane-app/src/bridge.ts#L72-L83), [capability API](../../packages/sane-app/src/bridge.ts#L2121-L2128), [frontend types](../../packages/sane-app/frontend/types.ts#L22-L30).
- **Current listeners:** one `Bun.serve` browser/API server with a 1 MiB request-body limit and `TerminalSocketData` websocket handler, plus a separate ephemeral loopback native-hook/worker/handoff server. Public origin changes the advertised/browser authority but does not configure a proxy. [Listeners](../../packages/sane-app/src/bridge.ts#L3007-L3012), [operator guidance](../../packages/sane-app/HUMAN-OPERATOR-GUIDE.md#L45-L48).
- **Current auth:** password is from `SANE_APP_PASSWORD`; browser sessions use an in-memory cookie token set and `HttpOnly; SameSite=Strict; Path=/` cookies (Secure for HTTPS). Host is checked before Origin; non-GET/HEAD requires exact Origin. Only specific same-machine proxy listener authorities may substitute for public Host, and forwarded headers are deliberately ignored. APIs require authentication after login/config routes. [Auth implementation](../../packages/sane-app/src/bridge-auth.ts#L21-L75), [API gate](../../packages/sane-app/src/bridge.ts#L2121-L2141).
- **Current remote admission:** a remote listener requires `allowRemote`, password, and public origin; non-loopback public origin also requires a password, and remote public origin must be exact HTTPS. This is App authorization, not automatically marimo authorization. [Config checks](../../packages/sane-app/src/app-config.ts#L134-L142), [bridge checks](../../packages/sane-app/src/bridge-auth.ts#L11-L16).
- **Current websocket support is terminal-specific**, not a general HTTP/WS relay. Terminal routes reject query parameters, explicitly validate Origin even on GET upgrades, obtain token-scoped resources, and recheck authorization after awaited preparation. Bun websocket data/handler is currently wired directly to `terminals.websocket`. [Upgrade route](../../packages/sane-app/src/bridge.ts#L2310-L2335), [server handler](../../packages/sane-app/src/bridge.ts#L3007-L3009).
- **Current backend can make local service HTTP calls/streams**, e.g. OpenCode service discovery keeps URL and credentials together, refuses automatic mutation replay, uses bounded HTTP requests and a bounded SDK event stream. This is a specialized adapter, not reusable reverse-proxy support for arbitrary web apps. [Discovery](../../packages/sane-app/src/opencode.ts#L88-L118), [stream adapter](../../packages/sane-app/src/opencode.ts#L124-L170), [request policy](../../packages/sane-app/src/opencode.ts#L172-L191).
- **Current process supervision examples:** terminal explicitly starts a shell after binding/auth checks and filters bridge/native env secrets; Claude launches a detached child with piped streams, checks shutdown/storage/ownership before spawn, and terminates both process group and direct child with bounded TERM/KILL escalation. These are implementation precedents, not a general child-process host. [Terminal launch](../../packages/sane-app/src/terminal.ts#L134-L181), [Claude launch](../../packages/sane-app/src/claude-run-service.ts#L319-L355), [Claude termination](../../packages/sane-app/src/claude-run-service.ts#L197-L218).
- **Current terminal cleanup caveat:** shell/job-control detached jobs cannot be guaranteed dead through `Bun.Terminal`; do not run marimo as an untracked terminal command and claim App ownership. [Terminal caveat/cleanup](../../packages/sane-app/src/terminal.ts#L422-L448).
- **Current ownership/lifecycle:** installation and App data ownership span build/start/serve/drain; failed cleanup retains ownership. Startup abort stops acquired listeners first, then bounds service cleanup. Normal shutdown has explicit feature drains and child termination before closing listeners/handles. Signal entry calls `bridge.close()`. A new service needs both normal-close and startup-abort hooks. [Ownership wrapper](../../packages/sane-app/src/bridge.ts#L124-L166), [abort](../../packages/sane-app/src/bridge.ts#L211-L245), [normal drain](../../packages/sane-app/src/bridge.ts#L3105-L3186), [signals](../../packages/sane-app/server.ts#L3-L14).
- **Current native plugin convention:** `opencode/plugins/sane/index.ts` uses `@opencode/plugin` to register SANE native tools and caller qualification; `nativeIntegrationConfiguration` emits OpenCode plugin plus Claude MCP/hook config. This establishes native harness integration only, with no frontend views or App extension loading. [Plugin](../../opencode/plugins/sane/index.ts#L8-L62), [configuration](../../packages/sane-cli/src/native-configuration.ts#L5-L14).
- **Current build uses one fixed App entry plus push worker** and hashes a conservative local workspace source closure; there is no extension frontend bundle discovery here. Runtime/dot directories and `.sane` are excluded. [Input closure](../../packages/sane-app/src/asset-build.ts#L28-L52), [entrypoints](../../packages/sane-app/src/asset-build.ts#L75-L87).

### Inferences

- **Proposal config:** accept one explicitly validated optional setting, e.g. `science: { enabled: false, executable: "/absolute/path/to/managed-python-or-marimo" }` or a tightly allowlisted `extensions.science` object. Either is a new schema addition, not proof of an extension framework. Default absent/disabled must produce no Python resolution, installation, process, listener, notebook directory, or native-agent changes. Reuse config-relative path semantics. An installation-level feature switch does not by itself mean every selected repository consents to code execution; opening/starting a notebook should still be explicit. [Strict config basis](../../packages/sane-app/src/app-config.ts#L18-L22), [paths/defaults](../../packages/sane-app/src/app-config.ts#L81-L108), [separate init principle](../../packages/sane-app/setup.ts#L8-L10).
- **Proposal package split:** `packages/sane-science` owns browser-safe DTOs/config validation and backend notebook confinement, manifest/association storage, marimo adapter, readiness/log bounds, port/auth management, and process lifetime. It may depend on `sane-core` for repository contracts/discovery but should not depend on `sane-app` or `sane-cli`. App owns thin adapters, shell UI, and browser auth; core/CLI remain unchanged initially. Export `/contracts` separately from `/server` as core does. [Existing split precedent](../../packages/sane-core/package.json#L6-L10), [existing repository API](../../packages/sane-core/src/server.ts#L26-L30), [App composition](../../packages/sane-app/src/bridge.ts#L40-L46).
- **Proposal optionality levels:** (a) Python/marimo are absent and never probed when disabled; (b) feature code can be in the workspace but lazily activated; (c) if the JS package itself must be physically absent, guarded optional loading and build-time UI packaging require an additional deliberate packaging solution. A hard static frontend import from an omitted package will break today's fixed-entry build. Do not equate a config toggle with install-time optionality; the repository packages are currently private workspaces, not published installable products. [Workspace privacy](../../package.json#L1-L6), [package privacy](../../packages/sane-app/package.json#L1-L4), [fixed build](../../packages/sane-app/src/asset-build.ts#L75-L87).
- **Proposal smallest transport:** explicitly local-only managed notebook server on a distinct loopback origin, its own authentication, dedicated Science iframe, external-open fallback, and no arbitrary upstream target selection. Bind cwd to the selected validated execution worktree but notebook files to the canonical Science root. The existing Browser is useful for a manually supplied prototype URL, not enough to deliver managed start/stop/files/auth. Remote clients must not be handed `127.0.0.1` as if it were the App machine. [No-proxy precedent](../../packages/sane-app/frontend/browser-tabs.ts#L7-L15), [remote limitation](../../packages/sane-app/frontend/browser-view.tsx#L69-L74), [binding precedent](../../packages/sane-app/src/catalog.ts#L149-L163).
- **Proposal remote-capable transport, only if required initially:** add a **fixed resource-scoped** HTTP plus websocket gateway to the known supervised loopback child, or an explicitly configured isolated notebook origin behind the operator's HTTPS proxy. Authenticate assets, pages, API, and socket upgrades—not just `/api/*`; preserve strict Origin checks, bounded streams/backpressure, aborts, header/cookie stripping, and logout revocation. Do not make a user-supplied URL proxy/SSRF surface. Review code execution's origin separately: same-origin proxying notebook scripts gives them App API privileges under the current frame grants. This transport is substantive new work; current HTTP adapters/terminal sockets are precedents, not a ready-made webview bridge. [Current API-only auth gate](../../packages/sane-app/src/bridge.ts#L2130-L2141), [terminal upgrade checks](../../packages/sane-app/src/bridge.ts#L2310-L2324), [frame permissions](../../packages/sane-app/frontend/browser-view.tsx#L7-L9), [operator proxy policy](../../packages/sane-app/HUMAN-OPERATOR-GUIDE.md#L45-L48).
- **Proposal lifetime:** one explicitly launched resource per notebook/execution-worktree scope with single-flight start, readiness deadline, generation pin, bounded logs, explicit stop/restart, process-group ownership and crash reconciliation. Wire termination into both startup abort and shutdown and do not put notebook work in conversation run limits/journals. Notebook execution is a separate resource category; if cleanup is uncertain, preserve an extension-owned recovery barrier and prevent duplicate launch. Existing App installation lock alone should not be assumed to arbitrate multiple installations accessing the same repository notebooks. [App ownership scope](../../packages/sane-app/HUMAN-OPERATOR-GUIDE.md#L20-L23), [termination precedent](../../packages/sane-app/src/claude-run-service.ts#L197-L218), [App cleanup seams](../../packages/sane-app/src/bridge.ts#L229-L245), [shutdown](../../packages/sane-app/src/bridge.ts#L3105-L3180).
- **Proposal no generic framework:** expose an explicit `ScienceService` with bounded request/status/start/stop/close operations and host-supplied repository/scope/auth callbacks. Avoid package discovery, arbitrary route/view registration, plugin lifecycle bus, generic extension permissions, or a new core schema merely to support one feature. [Explicit current service composition](../../packages/sane-app/src/bridge.ts#L40-L46), [static current UI composition](../../packages/sane-app/frontend/app.tsx#L175-L213), [strict config](../../packages/sane-app/src/app-config.ts#L9-L22).

### Gaps

- Exact marimo launch command, interpreter/environment provisioning, port selection/readiness, authentication method, graceful kernel termination, websocket semantics, and supported reverse-proxy base paths need separate component qualification; none is asserted here. Existing host limits/cleanup patterns only show what an adapter must integrate with. [Host limits](../../packages/sane-app/src/bridge.ts#L3007-L3009), [process cleanup precedent](../../packages/sane-app/src/claude-run-service.ts#L197-L218).
- Whether the product requires published independently installed `sane-science`, optional in-repository code, or simply opt-in Python/runtime behavior is not specified. Today's private workspace setup does not establish an extension distribution contract. [Workspace](../../package.json#L1-L6), [core exports/private package](../../packages/sane-core/package.json#L1-L12).

## 3. Where should notebooks live, and what is the minimum implementation surface?

### Takeaway

**Current blockers:** ordinary workspace APIs reject `.sane`, core artifact APIs accept Markdown rather than Python notebooks, and notebooks created in `.sane` before SANE initialization would make the store nonempty/incomplete. **Proposal:** after explicit successful domain initialization, use a separate canonical `<primary>/.sane/science/` namespace with extension-owned confinement/metadata, while keeping process cwd and research associations explicit. No core database migration or general extension framework is needed for this minimum. [File confinement](../../packages/sane-app/src/workspace.ts#L75-L123), [artifact path policy](../../packages/sane-core/src/server.ts#L42-L44), [store admission](../../packages/sane-core/src/repository.ts#L312-L354).

### Cited Findings

- **Current canonical `.sane` is primary-checkout-owned:** Git discovery finds the primary checkout, pins primary and invocation worktrees, sets `stateRoot = <primary>/.sane`, and database path to `.sane/sane.db`. It is not simply `process.cwd()/.sane`, and linked worktrees share repository state. [Discovery](../../packages/sane-core/src/repository.ts#L16-L55), [public discovery/context](../../packages/sane-core/src/contracts.ts#L24-L34).
- **Current execution versus artifacts roots are distinct:** invocation returns pinned execution checkout and canonical `.sane/workstreams/<id>` artifacts root. App routing validates selected execution binding against recorded conversation execution; browsing workspace/worktree selection is independently bookmarked. [Core context](../../packages/sane-core/src/server.ts#L490-L490), [App execution](../../packages/sane-app/src/workstreams.ts#L147-L166), [browsing versus execution contract](../../packages/sane-app/src/catalog-contract.ts#L14-L22).
- **Current `.sane` initialization hazard:** inspection considers absent/empty `.sane` uninitialized, but a nonempty directory without the database is incomplete and never adopted/overwritten. Initialization accepts only uninitialized/ready state and rejects unexpected files appearing in the fresh directory. Creating `.sane/science` first would therefore block later `sane init` and App conversation admission in that repository. [Inspect/init](../../packages/sane-core/src/repository.ts#L312-L354), [conversation admission](../../packages/sane-app/src/admission.ts#L25-L34).
- **Current post-initialization extension-directory compatibility:** safety/validation checks a fixed set of domain-owned paths, verifies completion marker and database binding, and requires `workstreams`/`locks`; it does not reject all extra root children in a ready store. This permits an extra `science/` namespace in principle, but does **not** supply any notebook-directory safety or validation guarantee. [Store safety/ready validation](../../packages/sane-core/src/repository.ts#L289-L310).
- **Current ordinary file APIs cannot access notebooks under `.sane`:** binding and lexical paths reject `.git`/`.sane`, App data, protected Git administration, traversal, and symlink access. Catalog also rejects selecting a directory under `.sane`, so registering `.sane/science` as an ordinary workspace is not an available workaround. [File checks](../../packages/sane-app/src/workspace.ts#L75-L123), [catalog discovery guard](../../packages/sane-app/src/catalog.ts#L79-L102).
- **Current core artifacts are Markdown:** artifact read/write rejects non-`.md`; artifact/document catalogs enumerate Markdown. Do not treat these APIs as generic Python notebook CRUD. [Policy](../../packages/sane-core/src/server.ts#L42-L44), [catalog/read](../../packages/sane-core/src/server.ts#L590-L645), [write](../../packages/sane-core/src/server.ts#L653-L665).
- **Current workstream tree has other semantics:** core full manifest enumeration hashes all files, while document catalogs enumerate Markdown and lifecycle provision/validation has established phase ownership. A large environment/cache/runtime tree under a workstream can interfere with artifact traversal/hashing even if notebooks are absent from document listings. [Full manifest](../../packages/sane-core/src/server.ts#L648-L652), [document traversal](../../packages/sane-core/src/server.ts#L608-L645), [validation expectations](../../packages/sane-core/src/validation.ts#L9-L28).
- **Current ignore behavior:** this checkout ignores root `.sane`; new standalone workspaces explicitly write `/.sane/` to `.gitignore`. The core initializer itself does not modify ignore rules. Consequently notebooks under `.sane` in these cases are not ordinary version-controlled source by default; init in other repositories does not establish a universal ignore contract. [Root ignore](../../.gitignore#L9-L12), [new-workspace helper](../../packages/sane-app/src/create-workspace-repository.ts#L14-L25), [core initializer](../../packages/sane-core/src/repository.ts#L330-L354).
- **Current search exclusions are independent of notebook discoverability:** recursive file/path APIs obey protected-path policies and safe nested `.gitignore`, skip dependency/build directories, and do not read global ignores or `.git/info/exclude`. A notebook needs dedicated discoverability rather than expecting Files search to expose it. [Search/path contract](../../packages/sane-app/src/workspace-contract.ts#L22-L31), [ignore contract](../../packages/sane-app/src/workspace-contract.ts#L48-L60), [hard `.sane` rejection](../../packages/sane-app/src/workspace.ts#L98-L101).
- **Current worktree creation is unavailable:** CLI USAGE explicitly marks worktree/destructive/candidate/merge operations unavailable; `sane-worktree-command.ts` exports unavailable stubs. ### Inferences

- **Proposal storage layout:** `<primary>/.sane/science/notebooks/<safe-id>.py` plus an extension-owned versioned manifest recording notebook ID, optional workstream/research association, and intended execution worktree binding. Keep generated data, environment, logs, secrets, and runtime ownership segregated (e.g. `.sane/science/runtime/`, or installation App data for installation-local process records); do not intermingle them with `.sane/workstreams` lifecycle documents or `sane.db`. Notebook extensions are assumed component input and must be validated by the adapter rather than generalized from core Markdown APIs. [Canonical root](../../packages/sane-core/src/repository.ts#L53-L54), [artifact distinction](../../packages/sane-core/src/server.ts#L42-L44), [full workstream manifest](../../packages/sane-core/src/server.ts#L648-L652).
- **Proposal initialization policy:** opening/listing a repository can show Science unavailable until explicit domain initialization. An explicit first-notebook workflow may offer existing SANE initialization, then create science state **only after** ready-domain validation. Do not silently create `.sane` on config enable/startup, and do not create notebook-only `.sane` stores. Supporting notebooks in App-only/plain-directory mode without domain init would require a different explicit storage policy or deliberate core init changes; defer that to avoid corrupting the current convention. [Initialization refusal](../../packages/sane-core/src/repository.ts#L312-L354), [router init seam](../../packages/sane-app/src/workstreams.ts#L91-L109), [app-only admission](../../packages/sane-app/src/admission.ts#L25-L34).
- **Proposal confinement:** validate the ready domain UUID/primary pin and selected catalog worktree binding, then construct only safe IDs beneath canonical `science/`. Reject traversal, symlink/hardlink aliases, special files, path replacement, and supplied arbitrary cwd/upstream URLs. Core only protects its own named store paths; science needs its own validation. Ordinary WorkspaceService must keep denying `.sane`. These guards secure host file operations, **not** arbitrary notebook Python execution; notebooks run trusted code with OS-user privileges unless a separate sandbox is deliberately built. [Domain safety scope](../../packages/sane-core/src/repository.ts#L289-L310), [workspace guard precedent](../../packages/sane-app/src/workspace.ts#L98-L154), [worktree binding](../../packages/sane-app/src/catalog.ts#L149-L163).
- **Proposal agent coexistence:** associate notebook paths/status/results with research conversations without making kernels native SANE assistant runs. Existing execution/workstream roots allow agent shell/filesystem activity to reference canonical notebook files; this is not a synchronized notebook tool API. If both user and agent edit the same file, define revision/conflict behavior and refresh semantics; do not initially promise simultaneous unsaved frontend edits and AI writes. Add optional notebook-native tools later only if ordinary file exchange proves insufficient; no skills/context changes are necessary for the architectural MVP. [Current context roots](../../packages/sane-core/src/contracts.ts#L31-L34), [native shell caller context](../../opencode/plugins/sane/index.ts#L50-L60), [execution root validation](../../packages/sane-app/src/workstreams.ts#L154-L166).
- **Proposal worktree behavior:** repository-shared notebook storage does not imply shared Python cwd/environment. Pin `(repositoryId, notebookId, worktreeId, bindingRevision)` for each running resource, display the execution root, and make cross-worktree relaunch explicit. Otherwise one notebook tab keyed only by workspace could silently execute against the wrong branch. Do not put managed worktrees beneath `.sane`, since catalog discovery rejects that path. [Separate browsing/execution](../../packages/sane-app/src/catalog-contract.ts#L14-L22), [current Browser workspace-only key](../../packages/sane-app/frontend/browser-tabs.ts#L18-L44), [binding](../../packages/sane-app/src/catalog.ts#L149-L163), [protected catalog paths](../../packages/sane-app/src/catalog.ts#L79-L86).
- **Proposal preservation:** `.sane` being ignored does not make scientific sources disposable. Specify backup/export (and optional deliberate export of a reproducible notebook source outside `.sane`) plus provenance/environment metadata. Do not change root `.gitignore` broadly or force-add `.sane`; that would expose domain state/secrets and is outside minimum integration. [Ignore evidence](../../.gitignore#L9-L12), [new-workspace ignore](../../packages/sane-app/src/create-workspace-repository.ts#L20-L23).

### Gaps

- Notebook version-control/backup expectations and source-of-truth under concurrent UI/agent edits are product contracts, not determined by today's ignored `.sane` state. [Ignored storage](../../.gitignore#L9-L12), [workstream documents versus execution roots](../../packages/sane-core/src/contracts.ts#L31-L34).
- A repository-level enablement/config file convention, notebook manifest schema, kernel ownership/recovery contract, and marimo environment are all **new** extension responsibilities. Existing ready-store allowance for extra directories must not be mistaken for an established extension convention. [Ready-store checks](../../packages/sane-core/src/repository.ts#L289-L310), [current config](../../packages/sane-app/src/app-config.ts#L9-L15).
- Whether notebooks must work without `sane init`, across multiple App installations, or on remotely connected clients must be resolved before implementation scope is fixed. These choices change storage and runtime/proxy scope substantially. [Init hazard](../../packages/sane-core/src/repository.ts#L312-L354), [installation ownership scope](../../packages/sane-app/HUMAN-OPERATOR-GUIDE.md#L20-L23), [frontend localhost semantics](../../packages/sane-app/frontend/browser-view.tsx#L69-L74).
