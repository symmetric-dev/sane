# External self-hosted issue trackers and adapters

Research snapshot: **2026-10-05**. Scope: upstream products only; no SANE repository architecture investigation, implementation, tests, or browser verification. Requirements supplied by the coordinator: simple workspace-scoped issue tracking in sane-app; issue state and operational configuration outside Git and `.sane`; no required skills, workstreams, or acceptance machinery; optional future links. Dates below were fetched from upstream GitHub APIs, not inferred from the calendar. “Latest” means the newest release returned during this snapshot, not a support/security guarantee.

## 1. Which current servers actually meet the licensing, maintenance, and deployment requirements?

### Takeaway

**Vikunja is the best lightweight external-server fit; Plane Community is the closest Linear-like fit; OpenProject Community is the mature, heavier fallback.** Huly is substantially more operationally complex, Taiga carries a larger agile-model/deployment surface, current Planka is not unrestricted open source, and standalone Focalboard explicitly lacks maintainers. These rankings are inferences grounded in the product evidence below, not measured benchmarks.

### Cited Findings

#### Vikunja

- **License:** server/frontend are predominantly **AGPL-3.0-or-later**; `desktop/` is GPL-3.0-or-later. This distinction is explicit in the upstream README, including the inspected release. Do not describe the entire repository as MIT or uniformly AGPL. — [Release README](https://github.com/go-vikunja/vikunja/blob/v2.7.0/README.md); [license](https://github.com/go-vikunja/vikunja/blob/main/LICENSE).
- **Edition boundary:** the free AGPL version is independently functional. Optional self-hosted Pro gates the admin panel, time tracking, and audit logs. Without a license key, the instance makes no license-check requests; with a key it checks at startup/daily, caches entitlements for up to 72 hours, and falls back to Community if invalid/unreachable beyond that period. Pro user caps apply to new active users, not a documented cap on Community. The feature page describes Pro as private beta, so availability of purchasable plans must be reconfirmed. — [Pro documentation](https://vikunja.io/docs/pro/); [features](https://vikunja.io/features/).
- **Maintenance:** GitHub returned **v2.7.0 published 2026-10-02**, preceding v2.6.0 on 2026-08-31; a default-branch commit dated 2026-10-04 was also returned. These are observed dates, not assumed October releases. — [v2.7.0](https://github.com/go-vikunja/vikunja/releases/tag/v2.7.0); [observed commit](https://github.com/go-vikunja/vikunja/commit/04373954353c22b78f552044ad551e1407a92f24); [release API](https://api.github.com/repos/go-vikunja/vikunja/releases?per_page=2).
- **Deployment:** the official image serves the app; supported databases include SQLite, PostgreSQL, and MySQL/MariaDB. SQLite needs **one app container**, persisting `/db` and `/app/vikunja/files`. The documented PostgreSQL example needs **two containers**, plus an optional TLS reverse proxy. Redis is optional and upstream says usually unnecessary for a handful of users. For more than a handful of users upstream recommends PostgreSQL or MySQL. — [Full Docker example](https://vikunja.io/docs/full-docker-example/).
- **Model/UI:** projects can contain subprojects; projects are shareable with users or teams; tasks have labels, priorities, assignees, attachments, relations/blocking, and list/table/Kanban/Gantt views. This is a task manager rather than a full Jira domain model. — [Features](https://vikunja.io/features/).

#### Plane

- **License:** upstream Community repository is **AGPL v3**. **Commercial is closed-source** and has a Free tier of **12 seats per workspace**; do not apply that Commercial seat limit to Community without separate evidence. Community has its own release cycle, no key requirement, and Free-cloud-tier feature parity, not Pro/Business/Enterprise parity. Airgapped is a Commercial-derived Enterprise Grid offering, not another free open-source edition. Commercial license keys bind to a workspace and machine. — [Actual license](https://github.com/makeplane/plane/blob/preview/LICENSE.txt); [Self-hosting 101](https://developers.plane.so/self-hosting/self-hosting-101).
- **Maintenance:** GitHub returned **Community v1.4.2 published 2026-08-23**, with a 2026-10-04 default-branch security-pin commit. No October Community release is inferred from that commit. Cloud/commercial freshness must not be substituted for Community release freshness. — [v1.4.2](https://github.com/makeplane/plane/releases/tag/v1.4.2); [observed commit](https://github.com/makeplane/plane/commit/7466675e471efe1c96b122615f7a0d30c9b2eb05); [release API](https://api.github.com/repos/makeplane/plane/releases?per_page=2).
- **Deployment:** inspected Community Compose defines **13 service entries**, including a one-shot migrator: web, space, admin, live, API, worker, beat-worker, migrator, PostgreSQL, Valkey, RabbitMQ, S3-compatible storage, and proxy. That is approximately **12 long-running services** in the stock topology, not a single lightweight server. The architecture overview also describes optional OpenSearch; it is not in this inspected stock Community Compose. PostgreSQL, upload storage, and queue/cache data have separate named volumes. — [Community Compose](https://github.com/makeplane/plane/blob/preview/deployments/cli/community/docker-compose.yml); [architecture/edition overview](https://developers.plane.so/self-hosting/self-hosting-101).
- **Model/UI:** the upstream app explicitly offers work items, cycles, modules, views, pages, and analytics. It is genuinely issue-centric but exposes more project-management concepts than required here. — [Upstream README](https://github.com/makeplane/plane/blob/preview/README.md).

#### OpenProject

- **License:** upstream code is **GPL v3**. Community is free with **unlimited users and projects**; Enterprise cloud/on-premises add-ons are separately gated. GPL source visibility does not imply every Enterprise feature is enabled in Community. — [Actual license](https://github.com/opf/openproject/blob/dev/LICENSE); [Community edition](https://www.openproject.org/community-edition/).
- **Maintenance:** GitHub returned **v17.9.1 published 2026-10-01** and v17.9.0 on 2026-09-30, plus a 2026-10-05 commit. This is actual observed October maintenance evidence. — [v17.9.1](https://github.com/opf/openproject/releases/tag/v17.9.1); [observed commit](https://github.com/opf/openproject/commit/a8e32669a9e184f9b1e55d771d932117f191672d); [release API](https://api.github.com/repos/opf/openproject/releases?per_page=2).
- **Deployment:** official stable/17 Compose has **nine service entries**, including one-shot seeder: PostgreSQL, memcached, proxy, web, autoheal, worker, cron, seeder, and Hocuspocus collaboration server. PostgreSQL and attachment assets persist separately. Production documentation recommends a TLS-terminating proxy and discusses backup/upgrade control scripts. Do not use its all-in-one evaluation image as evidence that production has zero operations overhead. — [Official Compose](https://github.com/opf/openproject-docker-compose/blob/stable/17/docker-compose.yml); [installation/operations](https://www.openproject.org/docs/installation-and-operations/installation/docker-compose/).
- **Model/UI:** issues are work packages in projects, with types, statuses, priorities, assignees and project-configured modules; the UI includes many broader PM modules. Basic boards do **not** change work-package attributes when moving cards; action/status boards do. The inspected general boards page describes behavior but does not clearly label every board type's current edition gate, so do not promise free automatic status boards based only on it. — [Work-package docs](https://www.openproject.org/docs/user-guide/work-packages/); [Boards docs](https://www.openproject.org/docs/user-guide/agile-boards/).

#### Huly

- **License:** platform and self-host deployment repository publish **EPL-2.0**. Cloud parity is not automatic: upstream says all cloud capabilities can *potentially* be self-hosted, some services/integrations are not prepackaged, and proprietary Cloudflare-dependent pieces are intentionally excluded from self-host packages. That is a packaging/dependency limitation, not evidence that all cloud services are included open source. — [Platform license](https://github.com/hcengineering/platform/blob/develop/LICENSE); [self-host repository/license](https://github.com/hcengineering/huly-selfhost); [self-host edition caveats](https://docs.huly.io/getting-started/self-host/).
- **Maintenance:** GitHub returned **platform v0.7.426 published 2026-07-05**, default-branch platform commit 2026-10-02, and self-host configuration commit 2026-09-29. The self-host repo returned no GitHub releases. Production guidance recommends platform `v*` tags and consulting `MIGRATION.md`, especially across 0.6→0.7. — [v0.7.426](https://github.com/hcengineering/platform/releases/tag/v0.7.426); [platform commit](https://github.com/hcengineering/platform/commit/b426f096ec8680e3b9650c8a84b8ca44c76553c6); [self-host commit](https://github.com/hcengineering/huly-selfhost/commit/ca3808a57c83518b971343df7d073753f38796ed); [upgrade guidance](https://github.com/hcengineering/huly-selfhost/blob/main/README.md).
- **Deployment:** upstream explicitly calls Huly resource-heavy: **minimum 2 vCPU/8 GB RAM, recommended 4 vCPU/16 GB+**. Current Compose includes CockroachDB, Redpanda, Elasticsearch, object storage and nginx, plus numerous services such as transactor, collaborator, accounts, workspace, frontend, fulltext, stats, and KVS. MongoDB, Redis/pulse, video, AI, calendar, export etc. are separately optional/configurable. Do not rely on old “MongoDB + MinIO only” descriptions for current 0.7. — [Requirements and operations](https://github.com/hcengineering/huly-selfhost/blob/main/README.md); [current Compose](https://github.com/hcengineering/huly-selfhost/blob/main/compose.yml).
- Upstream warns its provided CockroachDB/Redpanda configurations might not be production-ready, and offers explicit migration/volume-path controls. The platform's EPL license is **not** a license audit of all those independently licensed dependencies. — [README production warning and volume configuration](https://github.com/hcengineering/huly-selfhost/blob/main/README.md).

#### Taiga

- **License is component-specific:** inspected backend **6.9.0 and main are MPL-2.0**, while inspected frontend **6.9.0 is AGPL v3**. The Docker repository is MPL-2.0. Calling all of Taiga “AGPL” or “MPL” would obscure the actual component boundary. — [Backend 6.9.0 license](https://github.com/taigaio/taiga-back/blob/6.9.0/LICENSE); [Frontend 6.9.0 license](https://github.com/taigaio/taiga-front/blob/6.9.0/LICENSE); [Docker license](https://github.com/taigaio/taiga-docker/blob/main/LICENSE).
- **Maintenance:** backend default-branch commit **2026-09-28** fixes password-recovery token expiry. Docker configuration's observed last commit is **2025-10-13**, bumping the stack to **6.9.0**. Both inspected repositories returned no GitHub release objects; this does not mean they have no Git tags or container releases. Application activity and deployment-package freshness should be tracked separately. — [Backend commit](https://github.com/taigaio/taiga-back/commit/c8264ac6775103cbcc2a3a145978f2b475e9ff05); [Docker commit](https://github.com/taigaio/taiga-docker/commit/e12c106b265ab8c51ee7e62b744ffddd0f0d9771); [backend releases API](https://api.github.com/repos/taigaio/taiga-back/releases?per_page=2).
- **Deployment:** inspected standard Compose has **nine services**: PostgreSQL, backend, async worker, async RabbitMQ, frontend, event gateway, event RabbitMQ, protected attachments service, and nginx gateway. Production docs describe the separate REST, async, event and attachment components. — [Docker Compose](https://github.com/taigaio/taiga-docker/blob/main/docker-compose.yml); [production guide](https://docs.taiga.io/setup-production.html).
- **Model:** REST resources distinguish projects, user stories, tasks, and issues rather than treating them all as one simple issue object. The API and self-host docs expose ordinary integrations without a requirement for SANE workflow artifacts. No separately restricted self-host feature list was established in this research; do not infer cloud commercial parity from that absence. — [REST resource index](https://docs.taiga.io/api.html); [documentation](https://docs.taiga.io/).

#### Planka and Focalboard exclusions

- **Current Planka is fair-code/source-available, not an unrestricted open-source substitute.** The actual Community License v1.1, dated **2025-05-20**, allows personal/educational/internal-organization use and certain nonprofit cases, but prohibits third-party hosting for **any commercial gain, including indirect benefit**, and requires commercial licensing for cross-organization shared use outside the allowed cases. Files marked `.pe.`/Pro/Enterprise are separately licensed; non-main branches are stated to be unlicensed. This materially changes a SANE commercial integration/distribution analysis. — [Actual license](https://github.com/plankanban/planka/blob/master/LICENSE.md).
- Planka Community currently includes boards/cards, comments, custom fields, webhooks and documented REST; Pro gates OIDC SSO, guest roles and additional views/templates/export. Community→Pro migration is documented as one-way. Stock Community Compose is attractive operationally (**two services: Planka + PostgreSQL**), but simplicity does not cure license incompatibility with the stated open-source requirement. — [README edition matrix](https://github.com/plankanban/planka/blob/master/README.md); [Compose](https://github.com/plankanban/planka/blob/master/docker-compose.yml).
- Planka remains active: GitHub returned **v2.2.1 published 2026-08-10** and default-branch commit 2026-09-17. The exclusion is licensing, not an unsupported assertion of abandonment. — [v2.2.1](https://github.com/plankanban/planka/releases/tag/v2.2.1); [observed commit](https://github.com/plankanban/planka/commit/627701dda3459fa25830b0fd5bb2f5668d033284).
- Standalone **Focalboard explicitly states “currently not maintained”** and separates itself from Mattermost's Boards plugin. GitHub returned v8.0.0 on **2024-06-13**; the latest default-branch commit returned was **2025-06-11**, a dependency/CI update. Repo `pushed_at` was newer, demonstrating why pushed-at alone is not maintenance evidence. — [README warning](https://github.com/mattermost-community/focalboard/blob/main/README.md); [v8.0.0](https://github.com/mattermost-community/focalboard/releases/tag/v8.0.0); [observed commit](https://github.com/mattermost-community/focalboard/commit/a84bbb65e32edf972856b329417096ac413518e9).
- Focalboard licensing also needs precision: Mattermost-produced compiled versions are described as MIT, source for other builds as AGPL v3 or commercial, and specified admin/config/model areas as Apache-2.0. “Focalboard is MIT” is not an adequate description for building or modifying a server. — [Actual licensing policy](https://github.com/mattermost-community/focalboard/blob/main/LICENSE.txt).

### Inferences

- Shortlist **Vikunja → Plane Community → OpenProject Community**, ordered for the supplied simplicity requirement, not for enterprise breadth. Vikunja minimizes stateful dependencies; Plane improves issue-centric/Linear-like UX at the cost of a much larger stack; OpenProject is sensible if mature configurable project permissions/types matter more than a minimal UI. — [Vikunja deployment](https://vikunja.io/docs/full-docker-example/); [Plane features/stack](https://developers.plane.so/self-hosting/self-hosting-101); [OpenProject Community](https://www.openproject.org/community-edition/).
- Huly/Taiga remain technically possible but offer no compelling advantage for *simple* workspace issues over the shortlist that compensates for their deployment and domain-model complexity. — [Huly operations](https://github.com/hcengineering/huly-selfhost/blob/main/README.md); [Taiga architecture](https://docs.taiga.io/setup-production.html).
- Keep servers as independent network processes and use adapters instead of copying tracker source into sane-app. This maintains an architectural separation and avoids unnecessary forks; it is **not** a legal guarantee that integration/distribution has no copyleft obligations. Review the exact shipped combination, especially frontend embedding or tracker modifications. — [Plane license/vendor caveats](https://developers.plane.so/self-hosting/self-hosting-101); [Taiga frontend license](https://github.com/taigaio/taiga-front/blob/6.9.0/LICENSE); [Vikunja licensing](https://github.com/go-vikunja/vikunja/blob/v2.7.0/README.md).

### Gaps

- No benchmark deployment was performed; container counts are Compose service counts, not measured CPU/RAM, reliability, or user-capacity estimates.
- Dependency-license audits, image provenance/CVE audits, and enterprise contract terms were not completed. Huly's EPL label must not be extended to CockroachDB, Redpanda, Elasticsearch or external cloud services.
- Product docs can outrun a release. Select a pinned release and its API schema before committing to paid/Community feature availability; Plane's shared developer docs particularly need Community-specific verification.

## 2. What APIs, authentication, webhooks, MCP, and workspace mappings can an adapter actually use?

### Takeaway

Use **REST adapters** for Vikunja, Plane, OpenProject, or Taiga. Huly's documented examples instead expose a typed, WebSocket-backed SDK and therefore involve more protocol/model coupling; MCP is optional automation infrastructure, not a replacement for sane-app's issue UI.

### Cited Findings

| Product | Verified interface and authentication | Verified scope/events/MCP |
|---|---|---|
| **Vikunja** | REST **`/api/v2`**, standard verbs, PATCH, ETags/conditional requests, pagination envelope, runtime OpenAPI 3.1. Bearer API tokens or login JWTs; token route scopes. New integrations should use v2; v1 is frozen with future deprecation/removal documented, not yet assumed shipped. [API v2](https://vikunja.io/docs/api-v2/), [auth](https://vikunja.io/docs/api-documentation/). | Projects and user/team sharing; project/user webhooks. **Official built-in MCP in v2.7.0**, `/api/v2/mcp`, Streamable HTTP and scoped API token with `mcp:access`; not JWT. **Open-source implementation**, verified in release tag. [MCP help](https://vikunja.io/help/mcp/), [release source](https://github.com/go-vikunja/vikunja/blob/v2.7.0/pkg/modules/mcp/mcp.go), [webhooks](https://vikunja.io/docs/webhooks/). |
| **Plane CE** | REST; `X-API-Key` PAT, workspace-slug/project-ID routes, documented cursor pagination and 60 requests/minute per-key default. Self-host Compose exposes a configurable API key rate limit. Shared docs also describe OAuth, but **CE does not offer OAuth application registration**. [REST](https://developers.plane.so/api-reference/introduction), [CE OAuth limit](https://developers.plane.so/dev-tools/mcp-server-self-host), [Compose](https://github.com/makeplane/plane/blob/preview/deployments/cli/community/docker-compose.yml). | Native workspace→project→work item. - **Vikunja webhooks:** signatures use `X-Vikunja-Signature`, HMAC-SHA256 of raw body; default timeout is 30 seconds; **failed deliveries are not retried**. Private/loopback/link-local destinations are refused by default. A localhost-only sane-app therefore cannot assume webhooks will just work; use polling initially or a carefully controlled reachable receiver/egress configuration. — [Webhook technical documentation](https://vikunja.io/docs/webhooks/).
- **Vikunja authentication:** local login, OIDC, LDAP, TOTP and signup-disable controls are documented. MCP tokens select permitted actions but still inherit all projects accessible to that user: API route scopes are **not** per-project isolation by themselves. MCP OAuth is not currently supported according to the help page; HTTP bearer-token client support is necessary. — [Security/auth](https://vikunja.io/docs/security-hardening/); [MCP permissions/client caveats](https://vikunja.io/help/mcp/).
- **Plane webhook caution:** current shared docs describe v2 workspace-wide events, HMAC-SHA256 (`X-Plane-Signature`), event/delivery IDs, retries and work-item filters. They also reject private/localhost receiver URLs. These docs may contain Commercial/newer-cloud behavior; **CE webhook existence is credible, but do not assume v1.4.2 supports the entire documented v2/filter/retry surface without matching release source.** The inspected v1.4.2 backend has webhook allowlist/retention settings. — [Shared webhook docs](https://developers.plane.so/dev-tools/intro-webhooks); [v1.4.2 settings](https://github.com/makeplane/plane/blob/v1.4.2/apps/api/plane/settings/common.py).
- **OpenProject webhooks:** admin config can select projects and events including work packages, comments and attachments, and accepts a signature secret. The documentation describes API CORS allowlists separately from browser framing; these are not interchangeable. — [API/webhook administration](https://www.openproject.org/docs/system-admin-guide/api-and-webhooks/).
- **Taiga webhooks:** per-project events carry action/object type/data/change, with `X-TAIGA-WEBHOOK-SIGNATURE` **HMAC-SHA1**, not SHA256. Delivery can be synchronous/asynchronous depending on configuration; private-address controls and async-worker behavior need configuration attention. — [Technical webhook spec](https://docs.taiga.io/webhooks.html); [Docker stack](https://github.com/taigaio/taiga-docker/blob/main/docker-compose.yml).
- **Huly creation coupling:** the issue-create example increments a project's sequence, finds rank, uploads markup, then constructs a detailed tracker issue including status, number, kind, priority, estimation and rank. This is materially more involved than a small JSON REST create call. — [Actual upstream example](https://github.com/hcengineering/huly-examples/blob/main/platform-api/examples/issue-create.ts).

### Inferences

- **Recommended mapping:** keep one external connection plus one tracker scope per SANE workspace. For Vikunja map workspace→project (or root project with optional subprojects); for Plane map workspace→project within a shared Plane workspace, or workspace→native Plane workspace if stronger membership separation is needed; for OpenProject/Taiga map workspace→project; for Huly map workspace→Huly workspace + tracker project. These are proposed mappings, not native SANE integrations. — [Vikunja project model](https://vikunja.io/features/); [Plane API hierarchy](https://developers.plane.so/api-reference/introduction); [OpenProject project API](https://www.openproject.org/docs/api/); [Taiga project/resources](https://docs.taiga.io/api.html); [Huly workspace/space example](https://github.com/hcengineering/huly-examples/blob/main/platform-api/examples/issue-list.ts).
- Treat scope filtering as both adapter behavior and server authorization: make least-privilege tracker users/project memberships, bind the scope server-side, and reject issue IDs outside that scope. A broad user's token plus a UI filter is not a security boundary. Vikunja's documented MCP permission inheritance particularly illustrates this. — [Vikunja MCP permissions](https://vikunja.io/help/mcp/); [OpenProject context-sensitive capabilities](https://www.openproject.org/docs/api/introduction/).
- A minimal generic adapter can expose list/get/create/update/archive-or-close/comment/deep-link and metadata for statuses/labels/assignees; keep tracker-specific fields optional. Huly would need a richer SDK adapter and reconnect/version handling. — [Vikunja v2](https://vikunja.io/docs/api-v2/); [Plane REST](https://developers.plane.so/api-reference/introduction); [Huly examples](https://github.com/hcengineering/huly-examples/tree/main/platform-api/examples).
- Start with foreground refresh/polling and use webhooks as invalidation hints, not the sole durable source of truth. This avoids requiring an inbound public endpoint and tolerates Vikunja's explicitly non-retried delivery. Reconcile from REST after missed/offline events. — [Vikunja delivery behavior](https://vikunja.io/docs/webhooks/); [Plane receiver constraints](https://developers.plane.so/dev-tools/intro-webhooks).
- Optional future task/session/workstream references belong as external URLs or app-level relation metadata, **not required tracker status transitions or acceptance gates**. None of the verified basic CRUD APIs needs SANE skills/workstream acceptance. This is a requirements-derived integration proposal supported by those standalone resource APIs. — [Vikunja REST](https://vikunja.io/docs/api-v2/); [Plane REST](https://developers.plane.so/api-reference/introduction); [Taiga REST](https://docs.taiga.io/api.html).

### Gaps

- No verified upstream GraphQL integration was found for these candidates; REST/SDK evidence is the basis of the recommendations, not a claim that GraphQL can never exist.
- No upstream-official Huly, Taiga, Planka or standalone Focalboard MCP was established. Community MCP packages must be independently reviewed for license, credential handling and maintained self-host compatibility.
- Huly's docs point to a `platform-api#readme` URL, but a raw README at that path returned 404. Actual example files were successfully inspected instead. Generic webhook contracts and supported API-token flows remain unresolved.
- Plane current docs mix edition/version surfaces. Require endpoint/schema checks against the chosen Community tag before promising OAuth, the newest `/work-items` route, or current webhook-v2 features. No live instance was probed.

## 3. How should UI integration, server sharing, state storage, and effort be evaluated?

### Takeaway

For a real sane-app issue experience, prefer a small **native issue list/detail/create UI backed by an adapter**, with “Open in tracker” as escape hatch. Use **one shared server by default** and workspace/project mappings; treat authenticated iframe integration as an unverified extra, not the plan's foundation.

### Cited Findings

- **OpenProject framing is explicitly constrained:** inspected **v17.9.1** CSP sets `frame_ancestors("'self'")`, blocking a normal iframe from a different sane-app origin. Its CSP's `frame_src` concerns what OpenProject can frame, not who can frame OpenProject. Same-origin proxying could satisfy the ancestor condition but must also solve public URL, sessions, assets, CSP and path routing; it is not a proven turnkey embed. — [Release CSP source](https://github.com/opf/openproject/blob/v17.9.1/config/initializers/content_security_policy.rb); [API same-origin session requirement](https://www.openproject.org/docs/api/introduction/).
- **Plane:** release backend uses Django `XFrameOptionsMiddleware`; that is evidence about responses served by the backend, **not proof about every independently served frontend page**. Separate web/space/admin frontend services exist. No supported full authenticated UI embedding contract was established. Public Space functionality must not be confused with embedding a private issue-editing UI. — [Release middleware](https://github.com/makeplane/plane/blob/v1.4.2/apps/api/plane/settings/common.py); [separate services](https://github.com/makeplane/plane/blob/preview/deployments/cli/community/docker-compose.yml).
- **Taiga:** backend uses Django clickjacking middleware, while its static frontend and gateway are separate services. Again this is not conclusive evidence that the whole frontend can or cannot be framed. The production docs describe reverse-proxy configuration including a subpath, but not a supported authenticated iframe SDK. — [Backend middleware](https://github.com/taigaio/taiga-back/blob/main/settings/common.py); [production routing](https://docs.taiga.io/setup-production.html).
- **Vikunja:** upstream supports reverse-proxy deployments and documents `service.publicurl`, CORS origins, auth and persistent files/database; inspected route source does not establish a vendor-supported authenticated iframe contract. **Embedding remains unverified**, not “works because no blocking header was noticed.” — [Security/auth/proxy guidance](https://vikunja.io/docs/security-hardening/); [route source](https://github.com/go-vikunja/vikunja/blob/main/pkg/routes/routes.go).
- **Huly:** deployment documents nginx/public URLs plus multiple auth/WebSocket services and configurable OIDC. It does not establish a full-UI embedding API or framing guarantee. Its self-host requirements remain relevant even if the UI is merely launched rather than embedded. — [Self-host README](https://github.com/hcengineering/huly-selfhost/blob/main/README.md).
- **External persistence is supported:** Vikunja documents `/db` and `/app/vikunja/files` volumes; Plane uses named DB/cache/queue/upload volumes; Huly offers named volumes or absolute host paths such as `/var/huly/db`; OpenProject documents persistent PostgreSQL and assets volumes. These do not require issue state in the tracked application checkout. — [Vikunja](https://vikunja.io/docs/full-docker-example/); [Plane](https://github.com/makeplane/plane/blob/preview/deployments/cli/community/docker-compose.yml); [Huly](https://github.com/hcengineering/huly-selfhost/blob/main/README.md); [OpenProject](https://www.openproject.org/docs/installation-and-operations/installation/docker-compose/).

### Inferences

#### Recommended UI strategies, in increasing integration surface

1. **Launch/deep link: integration 1/5.** Save a workspace scope and open the tracker in the system browser. Reuse all tracker UI, preserve its origin/login, and avoid framing changes. This does **not** itself satisfy “issue tracking in sane-app” if users expect an in-app list/editor. It is a useful first bridge/escape hatch, not the final equivalent of a native tab. — [Standalone tracker UI/model](https://vikunja.io/features/); [OpenProject framing constraint](https://github.com/opf/openproject/blob/v17.9.1/config/initializers/content_security_policy.rb).
2. **Native minimal adapter UI: integration 3/5 for ordinary REST candidates.** Implement workspace-scoped list/detail, create/edit/status/priority/assignee, comments and tracker deep links. This adds one view/model adapter and credential/scope management but avoids replicating cycles, roadmaps or PM documents. Metadata, pagination and optimistic/concurrent updates are genuine integration work. — [Vikunja v2 semantics](https://vikunja.io/docs/api-v2/); [Plane pagination/auth](https://developers.plane.so/api-reference/introduction); [OpenProject HAL/capabilities](https://www.openproject.org/docs/api/introduction/).
3. **Full authenticated UI iframe/proxy: integration 4–5/5, unverified.** Needs security-header and cookie review, same-origin/base-path behavior, asset URLs, WebSocket upgrade routing and login redirects. A separate native WebView/browser surface may avoid iframe ancestor restrictions but introduces its own session/security implementation; it was not verified here. Do not globally strip CSP/X-Frame-Options as a shortcut. — [OpenProject release CSP](https://github.com/opf/openproject/blob/v17.9.1/config/initializers/content_security_policy.rb); [Plane service split](https://github.com/makeplane/plane/blob/preview/deployments/cli/community/docker-compose.yml); [Huly nginx/auth topology](https://github.com/hcengineering/huly-selfhost/blob/main/README.md).

#### Shared server versus per-workspace server

- **Default: one shared external server per user/team or trust boundary**, not one stack per checkout. Bind each sane-app workspace's stable identity to a tracker scope in app-level configuration. This amortizes backup/upgrade/auth overhead while using the documented project/workspace permission models. Local workspace display names or Git branch names should not be remote identity keys. — [Vikunja projects/sharing](https://vikunja.io/features/); [Plane workspace/project hierarchy](https://developers.plane.so/api-reference/introduction); [OpenProject webhook/project selection](https://www.openproject.org/docs/system-admin-guide/api-and-webhooks/).
- **Per-workspace deployment is an isolation option**, appropriate for different clients, data-residency/retention policies, or intentionally independent offline databases. It multiplies secrets, ports/domains, migrations and backups by workspace count. With `N` workspaces, stock Plane means approximately **12N long-running service instances**, whereas SQLite Vikunja means **N app containers** (both before shared/individual proxy choices). This arithmetic describes replicated stock topologies, not linear RAM/cost scaling. — [Plane Compose](https://github.com/makeplane/plane/blob/preview/deployments/cli/community/docker-compose.yml); [Vikunja SQLite example](https://vikunja.io/docs/full-docker-example/).
- A project/workspace ACL in one server is logical isolation, not separate process/database/administrator isolation. Shared servers require explicit permission checks and backup/export/delete behavior per mapped scope; choosing a shared service must not leak one workspace into another. — [Vikunja MCP inherited permissions](https://vikunja.io/help/mcp/); [OpenProject permission-aware API](https://www.openproject.org/docs/api/introduction/).

#### State outside Git and `.sane`

- Proposed local layout: connection mappings in sane-app's **application-level database/configuration**, credentials in the OS secret store or protected deployment secrets, and tracker data in explicitly named Docker volumes or absolute application-data paths outside all checkouts and `.sane`. Examples might be `~/Library/Application Support/<app>/issue-services/` on macOS or an operator-selected `/var/lib/<service>/` on a server. These are proposals, not verified existing SANE paths. — [Supported independent volume paths](https://vikunja.io/docs/full-docker-example/); [Huly absolute-path support](https://github.com/hcengineering/huly-selfhost/blob/main/README.md).
- Store deployment Compose/env files **outside the tracked SANE checkout too** if the user does not want PM/ops artifacts committed. Use explicit volume/project names rather than deriving data location from the current repo directory. Keep issue content authoritative only in the external tracker; a sane-app read cache, if used, should be application-level and not treated as a Git export. — [Named-volume behavior](https://www.openproject.org/docs/installation-and-operations/installation/docker-compose/); [Vikunja data mounts](https://vikunja.io/docs/full-docker-example/).
- Workspace removal must unlink the app mapping by default, **not delete shared tracker data or Docker volumes**. An explicit separate purge/export action can handle intentional destruction. Databases and attachment stores need coordinated backups outside the checkout. — [OpenProject persistence on stack removal](https://www.openproject.org/docs/installation-and-operations/installation/docker-compose/); [Vikunja backup/security guidance](https://vikunja.io/docs/security-hardening/).

#### Final recommendation for the coordinator

1. **Choose Vikunja first** if the user's chief need is a small workspace issue tab with open-source ownership and low operational load. Build against release-pinned REST v2; optional official MCP is already available in verified v2.7.0. Validate whether the task/board model provides the desired status and readable issue-identifier experience before selecting it. — [v2 API](https://vikunja.io/docs/api-v2/); [MCP](https://vikunja.io/help/mcp/); [features](https://vikunja.io/features/).
2. **Choose Plane Community second** if the Linear-like issue UI is worth operating a much larger stack. Keep Commercial/cloud edition claims separate; use PAT REST/stdio MCP and treat shared-doc feature parity as a release-specific question. Prefer native minimal UI + deep links over assuming a full editable embed. — [Edition/ops distinctions](https://developers.plane.so/self-hosting/self-hosting-101); [CE MCP limit](https://developers.plane.so/dev-tools/mcp-server-self-host).
3. **Keep OpenProject Community as the third, conditional option** when mature project roles/work-package configuration or an existing organizational deployment outweigh UI simplicity. Do not make its paid MCP or cross-origin iframe a prerequisite. — [Community](https://www.openproject.org/community-edition/); [Enterprise MCP gate](https://www.openproject.org/docs/system-admin-guide/integrations/mcp-server/); [framing policy](https://github.com/opf/openproject/blob/v17.9.1/config/initializers/content_security_policy.rb).

### Gaps

- **No browser/deployment verification was performed**, as requested. Actual sane-app origin, desktop-webview support, login-cookie behavior, selected proxy setup, and frontend response headers remain unknown.
- A proof-of-integration should be authorized separately: verify the pinned server's scope permissions, CRUD/comments/status semantics, offline/error behavior and deep links; test framing only if the user explicitly chooses it. Research notes are not evidence that an iframe works.
- Vikunja's board-column/status semantics and human-readable identifier requirements were not fully resolved against a deployed instance. These could alter the relative fit if Jira-style statuses/keys are essential.
- Shared Plane developer documentation may describe webhook/API functionality newer than Community v1.4.2. Preserve this uncertainty in the final report rather than silently attributing cloud/Commercial capabilities to CE.
